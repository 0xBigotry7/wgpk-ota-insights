# 定时检查

- 每 30 分钟：`POST /api/agent/heartbeat`。
- 每天 10:45（曼谷，定时任务）：写每日简报，见下。
- 每周一：拉过去 7 天的同口径数据做周复盘，把有效和无效的动作写进 notes（topic 周复盘）。

## 每日简报

数据只读一个接口：`GET /api/agent/daily`（全酒店 IDeaS、渠道 pace 与 pickup、严重预警、未关闭待办及其闲置天数、
数据新鲜度、昨天的简报、最近的 IDeaS学习笔记）。需要细节时再查单个接口，不要读整份 brief。

格式（中文，最多约 12 行，给 Gary 和老姚看）：
1. 全酒店（1–2 行）：IDeaS 快照日期；本月和下月在手对去年同期、预测入住率；未来 14 天里值得注意的日期（特殊事件、
   在手明显低于预测、LRV 高）。快照超过 3 天没更新就写“IDeaS 数据停在 X 日”。
2. 趋势（1–2 行）：各渠道各入住月的 pickup_1d / pickup_7d，差距在缩小还是扩大（和昨天的简报比）。没有变化写“无新变化”。
3. 今天要做的事（最多 3 条，每条：谁、在哪个后台页面、依据数字和日期、做完看什么）。渠道问题写成“该渠道份额/转化问题”，
   不说成全酒店缺口。和昨天一样的事不要再列，改写到第 4 段跟进里。
4. 跟进（1–3 行）：昨天简报里的事做了没有（数据有没有变化）；`open_todos` 里 idle_days ≥ 3 的写“#编号 负责人 X 天没动”，
   该关的建议关闭，该升级的写“需要 Gary 决定”。
5. 学习（到检查点日期才写，1 行）：按 IDeaS学习 笔记里的检查点打分——能打的打（方向对不对、和 IDeaS 比），没有的数据
   直说缺什么（全酒店实绩需要 OPERA 日报或新的 IDeaS 导出）。打分结果另存一条笔记 topic IDeaS学习。
6. 数据缺口（1 行）：只写今天和昨天不同的缺口；没变化写“缺口同昨天”。

每周一的简报在第 4 段后加一行“谁没动”：过去 7 天没有任何更新的待办，按负责人汇总条数和编号。

先 `POST /api/agent/notes` 保存（topic `daily-brief-YYYY-MM-DD`），再把简报原文作为最终回复输出。不要建待办。
